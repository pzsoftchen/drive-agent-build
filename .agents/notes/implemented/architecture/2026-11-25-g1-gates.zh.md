# Agent 决策记录：项目门禁

Status: implemented

[English](2026-11-25-g1-gates.md) | 中文

## 问题

DAB 已经能生成 docs、notes 和受管 authoring skills，也能用 `dab detect --strict` 发现配置漂移。它没有给消费项目一个稳定的本地执行入口。生成的实践可能长期不运行，`detect` 只是检查器而不是每天执行的命令，Java/iOS/Android 项目没有命令适配，也没有同变更检查的位置。G4 在 0.1.2 关闭了受管 skill 更新之后，G1 是最高优先级的执行层缺口。

## 决策

- `.agents/gates.yaml` 是 authored、project-only。它使用严格的 version-1 schema，包含固定的 `required` source gate，以及 `code` 命令，名称为 `test`、`typecheck`、`lint` 和 `build`。`docs` 需要 `mode`；只有 command 可选。Mode 为 `required`、`check`、`advisory` 和 `off`。
- `scripts/dab-gates.json` 是 normalize 从 authored 配置编译的生成快照。Scanner 输出只在配置缺失时生成 starter，永不回填已有配置。它的 SHA-256 覆盖规范化的 `gates` 对象。`scripts/dab-check.mjs` 是带 `// dab-gate-runner: <version> sha256=<hash>` marker 的稳定 runner。runner 读取快照，不内嵌项目命令，也不解析 YAML。这样 runner 保持稳定，命令仍然是可评审的配置。
- runner 先执行固定 `source` gate（`dab detect --strict`），再执行每个已配置的 code 和 docs 命令，不短路。DAB 二进制只按 `DAB_BIN`、本地 `node_modules/.bin/dab`、`PATH` 和 `npx --no-install @saydone/dab` 的顺序解析。缺少 DAB 二进制是 `ERROR`；未解析命令或无效、缺失快照是 `CONFIG`；两者都退出 `2`。required 失败退出 `1`；`--strict` 还会提升 check 和 advisory warning。`mode: off` 是显式 `SKIP` 豁免；被删除的 scanner 必需 `test`/`typecheck` 在未显式 off 时是检测 error。
- Init 和 normalize 创建缺失的门禁文件。Normalize 只替换未修改的较旧 runner 或过期快照；被修改、无版本和较新的生成文件会保留并产生 warning。planning 和 apply 之间发生变化的文件以 `verification.artifact-concurrent-change` 保留。无效 authored 配置会阻止所有写入，因此 DAB 不会写入部分门禁文件。
- scanner 只读取文件，检测 Node、Python、Go、Rust、Java Maven、Java Gradle、Android、iOS SwiftPM 和 iOS Xcode。Maven 和 Gradle 优先 wrapper（`mvnw`/`gradlew`，runner 在 Windows 上使用 `.cmd`/`.bat`）；Android 抑制重复的 Java Gradle 命令；SwiftPM 抑制 Xcode test 命令。只有 Xcode 的项目保持 `needs-config`，使用 `command: null` 和 `needs` 说明，直到项目提供 `project`/`workspace` 二选一，加上 `scheme` 和 `destination`，或 Fastlane 命令。DAB 不运行 `xcodebuild -list`，也不选择模拟器。
- `dab detect` 增加 project-only 的 `Verification` 组。缺失 config、runner 或快照，以及未修改但过期的产物，是会让 `--strict` 失败的 warning。无效、不可读或格式错误的配置是 error，`verification.command-missing` 和 `verification.artifact-path` 也是 error。`verification.command-needs-config` 会让 `--strict` 失败。被修改、无版本和较新的产物、`verification.commands-empty` 以及 `verification.ci-missing` 保持非 strict。`verification.starter-invalid` 报告 DAB 自身 bug。
- G1 不新增 `dab` 命令。source gate 复用 `dab detect --strict`，项目在自己的 CI 中调用生成的 runner。DAB 不生成 CI 文件，不探测构建工具，也不实现 G9 的同变更门禁。

## 备选方案

**新增 `dab check` CLI 命令。** 被拒绝：G1 要求不新增命令，项目本地 runner 必须能在 CI 中工作，不能让 DAB 成为唯一入口。

**把项目命令嵌入生成的 runner。** 被拒绝：每次改命令都要重写可执行代码，review 会比较代码而不是配置，runner 也会偏离 pre-commit、Nx 和 Turborepo 使用的稳定 runner 模式。快照让命令保持声明式，runner 保持稳定。

**只生成 shell 脚本。** 被拒绝：Java 和 Android 项目可能在 Windows 上开发，而 Node 已是 DAB 前置条件。runner 在 Windows 上规范化 `./mvnw` 和 `./gradlew`；DAB v0.1 CLI 本身仍拒绝 Windows，因此完整门禁支持要等待平台支持。

**自动生成 CI workflow。** 被拒绝：CI provider、权限、分支策略和发布流水线因项目而异，workflow 是安全敏感文件。v1 提供文档片段和非 strict 的 `verification.ci-missing` warning。

**在 init 时运行 `xcodebuild -list` 或 `gradle tasks`。** 被拒绝：这些探测可能依赖 SDK、网络或时间，而且仍不能证明项目想要的 destination。显式项目配置才是契约。

**复制 deepseek-harness 的 `check:all`。** 被拒绝：它的门禁清单是项目特定的。DAB 复用聚合机制和技术栈适配，而不是业务命令。

## 后果

- 项目获得一个本地和 CI 入口 `node scripts/dab-check.mjs`，支持 `--strict` 和 `--json`。本地和 CI 的一致性来自执行同一个文件，而不是生成的 workflow。
- source gate 需要 DAB 二进制。没有它时 runner 报告 `ERROR` 并退出 `2`，不会跳过 DAB 检查。
- Xcode 项目有意不做零配置：未配置的项目会报告 `verification.command-needs-config` 和 runner `CONFIG`，直到有人提供 shared scheme 和 destination 或 Fastlane 命令。
- starter 选择一个主技术栈，每个维度一个命令。需要多个技术栈 test 命令的混合仓库必须覆盖 `.agents/gates.yaml`；v1 没有多命令维度。
- 被修改、无版本和较新的门禁产物会保留，直到有人核对。Normalize 永不覆盖或降级它们，因此 `detect` 可能持续 warning。
- 空配置加空扫描只是 warning。`detect` 让 `verification.commands-empty` 保持非 strict，因为它描述项目状态；而 runner 的 `--strict` 会把它 `WARN` 变成退出码 `1`；两个工具的行为有意不同。
- CI 接线仍然手动，缺少 CI 是非 strict，因此项目可以先在本地采用门禁，再修改流水线。
- G1 已随 `0.1.3` 发布；`package.json` 版本提升和打 tag 由发布准备单独完成。G9 同变更门禁、显式 opt-in 的 CI 生成器和 eval 证据仍然推迟。

## 验证

- `pnpm test`：71 个测试文件、954 个测试通过。
- `pnpm typecheck`：无错误。
- `pnpm doc-sync`：配对、链接、排版、预算和 Agent 决策记录检查通过。
- `pnpm build`：TypeScript 编译通过。
- `node dist/cli.js detect --strict`：退出 `0`，`25/26 (96%)`；唯一 warning 是非 strict 的 CI 接线缺失。
- `node dist/cli.js normalize --dry-run`：dogfood normalize 后没有待写入内容。
- `node scripts/dab-check.mjs --strict`：退出 `0`；source、test、typecheck 和 build 通过，docs 报告 `SKIP`。
- Node fixture：`dab init` 后运行 `node scripts/dab-check.mjs --json`，报告 source、test、typecheck 和 build gate；source gate 和 code test 都实际执行。
- 只有 Xcode 的 fixture：init 写入 `command: null` 和 `needs` 说明；detect 报告 `verification.command-needs-config`，runner 报告 `code.test CONFIG` 并退出 `2`，绝不假通过。
- `git diff --check`：干净。
