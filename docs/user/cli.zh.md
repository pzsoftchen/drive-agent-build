# CLI

公开命令是 `dab`。所有命令都支持 `--json`，退出码区分配置用法、校验和后端问题。

## 安装

```bash
npx @saydone/dab --version
npx @saydone/dab init /path/to/project
```

或者全局安装后使用 `dab`：

```bash
npm install -g @saydone/dab
dab --version
```

npm 包名是 `@saydone/dab`；`npx dab` 会解析到另一个包。需要 Node.js `>=24.9`、Claude Code `>=2.1.277`、macOS 或 Linux。

## Scope 与 Root 发现

| 命令 | Root |
|---|---|
| `dab init [path]` | 确切的 `path` 或当前目录 |
| 其他命令 | 最近的、包含 `dab.yaml` 或 `.agents/` 的祖先目录 |

- 运行 `dab init ~/.agents` 引导 global scope。
- 从子目录运行时，其他命令向上查找到最近的项目 manifest 或 source tree。
- 位于 `$HOME/.agents` 内时，命令使用 global scope；global source root 始终是 `$HOME/.agents`。
- Project 和 global scope 独立检查和 normalize。没有 `dab global` 命令，也没有跨 scope 合并。
- Adoption 在需要 manifest 之前先解析 phase：`initialized` 表示 manifest 可解析且 `.agents/` 存在，`partial` 表示只有一个 marker 或 manifest 无效，`uninitialized` 表示两者都不存在。
- 未初始化的 project 以最近的、包含 `.git` 的祖先目录为根，找不到时使用当前目录。
- Global scope 要求 `~/.agents` 存在；完全缺失时先运行 `dab init ~/.agents`，再做第一次 global 检查。
- v0.1 的所有命令都拒绝 Windows。

## `dab init`

```bash
dab init [path] [--profile generic|feature] [--ai] [--dry-run]
```

Project 布局：

```text
AGENTS.md
dab.yaml
.agents/
.claude/            generated by dab normalize
```

Global 布局：

```text
~/.agents/AGENTS.md
~/.agents/dab.yaml
~/.agents/agents ... policies, notes; hooks and memory are opt-in
~/.claude/agents ... generated projections under $HOME
```

- `dab init ~/.agents` 初始化 global scope：编写源位于 `~/.agents/`，投影位于 `$HOME` 下。
- `dab init path` 把 `path` 作为确切的 source root，并在缺失时创建它。它拒绝在已有 source root 内部创建 source root。
- 扫描仓库并写入缺失的编写文件。编写源冲突会在写入前停止。`.agents` source parent（`agents`、`hooks`、`memory`、`notes`、`policies`、`adapters`、`rules`、`skills`）处的普通文件、悬空链接或不可访问状态是受治理的冲突，会阻止所有写入。非 import 的未受管 `.claude` 冲突会作为 pending 报告，交给 `dab normalize --fix`。
- Init 从不导入现有 `.claude/agents` 或 `.claude/skills` 条目，也不会为它们创建 adoption 备份。Import 是 `dab normalize` 的职责。
- 高级 hooks 和共享记忆默认不生成。`.agents/hooks/` 和 `.agents/memory/` 是可选能力；已有 hooks 会被校验并在适用时编译，已有记忆会被保留和校验。
- 生成的 manifest 是 v2，包含 `scope`、`profile`、`docs.language`、`targets` 和 `instructions: symlink`。`--profile` 接受 `generic`（默认）或 `feature`；`feature` 是行为相同的兼容别名，且从不覆盖已有的 authored manifest。
- `docs.language` 控制项目文档语言：`auto`（默认）、`en` 或 `zh`。`auto` 依次采样现有的 `docs/AGENTS.md`、`docs/architecture.md`、根 `AGENTS.md`、`README.md`、`package.json` description，然后读取 locale；没有任何信号时使用 `en`。Init 输出 `Language: <value> (source: <source>)`，JSON 追加 `language: { value, source }`。
- Init 写入两个单语文件 `docs/AGENTS.md` 和 `docs/architecture.md`，不生成 `.zh.md` 或 `.i18n.yaml` 配对。`docs/AGENTS.md` 是 AGENTS 文件，继续豁免配对。已有文档永不被覆盖。
- Init 安装 `dab-doc-writing`、`dab-architecture-writing` 和 `dab-decision-notes` skills，位于 `.agents/skills/` 下。已存在的 skill 目录会保留，并报告为 skipped。每个安装文件都带 `<!-- dab-skill: <name>@<version> sha256=<hash> -->` 标记。当只有可导入的 `.claude/skills/dab-<name>` 目录存在时，init 跳过对应的 authoring 模板，以 `practice.skill-import-pending` 报告为 pending，并把 import 留给 `dab normalize`。非目录条目无法导入：init 跳过模板，以 warning pending 报告 `practice.skill-import-conflict`，且从不写入或替换物理条目。
- Generic skeleton 不生成 `.agents/rules/docs-bilingual.md`；已有的 authored 规则会保留。当该规则存在时，缺失的 documentation targets 以 `practice.docs-bilingual-policy` 被 policy skip；已有 docs 作为 skipped 保留。在其他方面安全时，init 仍安装 authoring skills 并写入 target 输出。
- JSON 输出包含 `root`（source root）和 `scopeRoot`（路径基准）；`created`、`skipped` 以及嵌套 normalize 路径都相对于 `scopeRoot`。
- `--dry-run` 预览编写文件写入和 pending 冲突，不写入任何内容。`--ai` 让 Claude Code 生成提案，确认后才写入；提案通过内置 profile 相同的 authored scaffold planner 渲染，且 `--ai` 不能与 `--dry-run` 同时使用。

## Manifest v2

```yaml
version: 2
scope: project
project:
  id: example
  name: Example
profile: generic
docs:
  language: auto
targets:
  - provider: claude-code
    enabled: true
    options:
      minVersion: 2.1.277
      instructions: symlink
paths:
  agents: .agents
  claude: .claude
generated:
  targets:
    - provider: claude-code
      settings:
        path: .claude/settings.json
        sha256: 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
      instructions:
        path: .claude/CLAUDE.md
        mode: symlink
        sha256: 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
      projections: []
```

Global manifest 位于 `~/.agents/dab.yaml`，声明 `scope: global`：

```yaml
version: 2
scope: global
project:
  id: personal
  name: Personal
profile: generic
docs:
  language: auto
targets:
  - provider: claude-code
    enabled: true
    options:
      instructions: symlink
paths:
  agents: .agents
  claude: .claude
```

- `profile` 为 `generic`（默认）或 `feature`；`feature` 作为兼容 profile 保留给已有工作流，并获得相同的实践行为。
- `docs.language` 接受 `auto`（默认）、`en` 或 `zh`；显式 `en` 或 `zh` 跳过检测。设置 `language: zh` 可在不检测的情况下生成中文文档：

  ```yaml
  docs:
    language: zh
  ```

- `scope` 必须匹配解析出的位置；不匹配是错误。
- `targets` 是必需的，且至少包含一个条目。单个条目可以设置 `enabled: false`；必须至少保留一个启用的 target，否则 normalize 和 detect 会以 `target.none` 失败。
- 启用的 target 没有 adapter 时会以 `target.unsupported` 失败。
- `generated` 由 `dab normalize` 写入；永远不要手工编辑。
- Legacy v1 manifest 会按 project scope 迁移到 v2。

## `dab detect`

```bash
dab detect [--strict] [--json]
```

只读运行。它会在需要 manifest 之前解析 scope 和 adoption phase，因此未初始化或 partial scope 会返回 checklist，而不是 source-root 错误。随后它校验 scope、启用的 target adapter、Claude Code 版本、祖先指令文件、指令产物、投影、settings、策略、存在时的可选 hooks 和记忆、敏感信息、文档实践、AGENTS.md 大小和链接。

人类输出先打印 `dab detect`，再打印 `Scope`、`Root` 和 `Profile`，按 Instructions、Documentation、Agents、Skills、Rules、Policy、Hooks、Memory、Notes、Generated target 和 Safety 分组，然后打印 `score: <ok>/<total> (<percent>%)`，并为每个不同的下一步输出一行 `next:`。下面的示例取自一个新的 generic project：先运行 `dab init`，再运行 `dab detect`，其中 root 替换为 `/path/to/project`。路径、版本和 score 取决于项目和已安装的 DAB 版本。Hooks 和 Memory 只在项目存在可选的 `.agents/hooks/` 或 `.agents/memory/` 文件时出现，因此新项目不显示这两个组。

```text
dab detect
Scope: project
Root: /path/to/project
Profile: generic

Instructions
  [OK] AGENTS.md
  [OK] .claude/CLAUDE.md

Documentation
  [WARN] docs/AGENTS.md (Language: en (source: docs/AGENTS.md); TODO markers at line 20, 29, 42, 48) -> use dab-doc-writing
  [WARN] docs/architecture.md (Language: en (source: docs/AGENTS.md); TODO markers at line 13, 17, 21, 25, 29, 33, 37, 41, 42, 43, 44, 45) -> use dab-architecture-writing

Agents
  [OK] implementer
  [OK] reviewer

Skills
  [OK] dab-doc-writing (version 0.1.1)
  [OK] dab-architecture-writing (version 0.1.1)
  [OK] dab-decision-notes (version 0.1.1)
  [OK] doc-sync
  [OK] feature-delivery

Rules
  [OK] generated-files
  [OK] testing

Policy
  [OK] project

Notes
  [OK] .agents/notes/

Generated target
  [OK] .claude/settings.json

score: 14/16 (88%)
next: use dab-doc-writing
next: use dab-architecture-writing
```

| 状态 | 含义 |
|---|---|
| `[OK]` | 事实符合。 |
| `[MISSING]` | 应有的事实或产物缺失。 |
| `[WARN]` | 非致命问题，例如漂移或环境警告。 |
| `[ERROR]` | 需要修复的错误。 |
| `[IMPORTABLE]` | 物理 `.claude/agents` 或 `.claude/skills` 条目，可由 `dab normalize` 导入 `.agents`。 |

- `score` 统计全部条目中 `[OK]` 的比例；其他状态都不计入 OK，且 score 永不改变退出码。
- Hooks 和 Memory 条目从不报告缺失的可选文件；没有这些文件的项目不会被报告为缺失。
- 已初始化 scope 与未初始化 scope 运行同一份只读 import 计划，因此可导入条目会报告为 `[IMPORTABLE]`，而不是 unmanaged 或 physical-copy 投影漂移。
- `.agents` source parent（`agents`、`hooks`、`memory`、`notes`、`policies`、`adapters`、`rules`、`skills`）处的普通文件、悬空链接或不可访问状态在其分组中报告为 `[ERROR]` `path.conflict`；project 的 `rules` 和 `skills` practice parents 保持 `practice.docs-path` 和 `practice.skill-path`。Secret scan 是尽力而为，可能跳过不可读子树；source-parent 访问错误由 parent probe 报告。
- 不可读的嵌套 skill 目录会为该 skill 报告 `[ERROR]` `skill.unreadable`。同级 skills 仍保留其事实和投影，运行结果绝不会被报告为健康。
- `phase` 为 `initialized` 表示 `dab.yaml` 可解析且 `.agents/` 存在；只有一个 marker 或 manifest 无效时为 `partial`；两者都不存在时为 `uninitialized`。
- `Profile` 来自有效的 manifest；未初始化 scope，或没有有效 manifest 的 partial scope，显示 `not initialized`。
- `Documentation` 组出现在所有 project phase，global scope 不显示。Preflight（未初始化和 partial scope）只检查存在性、policy skip、语言和路径状态；内容检查在已初始化 scope 运行。没有双语规则时，缺失的 docs 为 `[MISSING]`，next 为 `dab normalize`；存在规则时，它们是 `[WARN]` policy skip，next 为删除规则。在已初始化 scope 中，内部链接损坏为 `[ERROR]`；行首 `TODO:` 或 `TODO(owner):` 标记和空架构章节为 `[WARN]`，next 为 `use dab-doc-writing` 或 `use dab-architecture-writing`。每个条目的 detail 都包含 `Language: <value> (source: <source>)`。manifest 无效的 partial scope 仍显示该组，但不提供 `dab normalize` next action。
- `Skills` 组报告 `dab-doc-writing`、`dab-architecture-writing` 和 `dab-decision-notes`。缺失 skill 为 `[MISSING]`，next 为 `dab normalize`；路径冲突为 `[ERROR]`，已存在但非法的 `SKILL.md` 由 source discovery 报告，不会被当作已保留。Preflight（未初始化和 partial scope）只报告存在性、policy skip、语言和路径状态。在已初始化 scope 中，当前 marker 为 `[OK]`；未修改的较旧版本为 `[WARN]`，next 为 `dab normalize` 并给出 `practice.skill-stale` warning；legacy marker 为 `[WARN]`，body 与模板一致时可迁移；较新或无法比较的版本、body 与 marker hash 不再匹配、缺失 marker 和指向其他 skill 的 marker 都为 `[WARN]` 并保留；路径或读取错误为 `[ERROR]`。
- `--strict` 会在 practice 文件缺失、TODO 标记、空架构章节、落后 skill 标记和其他 practice warning 时失败。`practice.docs-bilingual-policy`、`practice.skill-newer`、`practice.skill-modified`、`practice.skill-legacy`、`practice.skill-marker-mismatch` 和 `practice.skill-unversioned` 保持信息性，因为它们描述项目政策或保留的 authored 内容。
- 未初始化和 partial scope 始终退出 `2`，且从不写入；`--strict` 不改变这一点。
- 已初始化 scope 保持现有退出码：干净时为 `0`，`--strict` 警告和校验失败退出 `3`，Claude Code 版本不兼容退出 `4`。
- `--strict` 在存在项目或配置类警告（如 unknown frontmatter 或漂移）时以 `3` 退出；环境类警告（如缺少 Claude Code 可执行文件）不会失败。
- Global scope 会跳过祖先和个人记忆检查，因为用户级 Claude 数据不是项目产物。
- Global scope 下 `~/.claude/settings.json` 和 `$HOME/.gitignore` 归用户所有且只读；global settings 不会被采用。
- Unmanaged target path 和缺失的生成记录会作为漂移报告。

`--json` 保留 `targets`、`diagnostics`、`summary` 和 `schemaVersion: 1`，并追加 `scope`、`root`、`phase`、已知时的 `profile`，以及 `checklist`、`score` 和 `nextActions`。每个 checklist 条目包含 `group`、`label`、`status`、可选的 `detail`、可选的 `file` 和可选的 `next`。`checklist` 包含 `Documentation` 组和 `Skills` 中的 authoring skill 条目；解析出的语言以文本形式放在 `detail` 中，不新增结构化字段。

未初始化和 partial scope 返回这一完整结果对象，其中 `ok: false`、`exitCode: 2`；不再使用保留给用法、校验和后端错误的 `{ ok: false, error }` 信封。由于字段只是追加，`schemaVersion` 仍为 `1`。

## `dab normalize`

```bash
dab normalize [--dry-run] [--fix] [--json]
```

规划或应用 authored source adoption、Claude import、缺失的 documentation 和 authoring skills、受管 authoring-skill 更新、投影修复、`.claude/CLAUDE.md` 指令产物、`.claude/settings.json`、`dab.yaml` 生成记录和 `.gitignore`。它在写入 target 输出前预检每个启用的 target；一个 target 失败会阻止所有 target 写入。`--fix` 会在替换前把非 import 的冲突路径备份到 `.dab/backups/`。

- Adoption 在 source-root 解析前运行。未初始化或 partial 的 project 会获得缺失的最小 authored source：`AGENTS.md`、`dab.yaml`、`.agents/policies/project.yaml` 和 `.agents/adapters/claude-code.yaml`，以及空的 `.agents/agents`、`.agents/skills`、`.agents/rules` 和 `.agents/notes` 目录。Hooks 和共享记忆是可选能力，不会被采用。已有 hooks 由 `init`、`normalize` 和 `detect` 校验并在适用时编译；已有记忆文件由 `init` 和 `normalize` 保留，并由 `init` 和 `detect` 校验。Global scope 使用 `.agents/AGENTS.md` 和 `.agents/dab.yaml`（位于 `$HOME`）以及相同的 source 子目录。它从不创建 profile 的默认 agents 或 core skills；命名空间的 `dab-*` authoring skills 是例外。full profile skeleton 请使用 `dab init`。
- Normalize 在 project scope 补齐缺失的 practice artifacts。未初始化或 partial project 的 adoption 包含 documentation 和 authoring packs；已初始化 project 的 convergence 只补缺失的 docs 和 `dab-*` skills。脚手架从不覆盖已有 docs 或 skill 目录，`--fix` 也从不替换或备份 authored practice 路径；仅有的受管重写是未修改的较旧 `SKILL.md` 和逐字节一致的 legacy `SKILL.md` marker 迁移。
- 当 `.agents/rules/docs-bilingual.md` 存在时，缺失的 documentation targets 以 `practice.docs-bilingual-policy` 被 policy skip；已有 docs 作为 skipped 保留，规则本身保留。Authoring skills 仍会安装，target 写入继续。
- 阻断性的 source 或 practice 错误（`.agents` source parent 处的普通文件、悬空链接、访问拒绝或符号链接循环，逃逸链接或不可读路径）会阻止所有写入，包括 `.claude`。Practice 写入发生在 target planning 之前，因此新 skill 会在同一次运行中被投影；后续 target 失败会保留幂等的 practice 文件，重跑是安全的。
- 已安装的 `dab-*` skills 是带 `<!-- dab-skill: <name>@<version> sha256=<hash> -->` 标记的 authored 副本；hash 覆盖移除 marker 行后的 UTF-8 body。Normalize 会创建缺失 skill，更新 marker 版本严格早于已安装 DAB 版本且未修改的副本，并在无 hash 的 legacy marker 去掉后 body 与当前模板逐字节一致时迁移该 marker。它会保留并警告已修改 body（`practice.skill-modified`）、较新或无法比较的版本（`practice.skill-newer`）、不同的 legacy body（`practice.skill-legacy`）、缺失 marker（`practice.skill-unversioned`）和指向其他 skill 的 marker（`practice.skill-marker-mismatch`）。仅有 CRLF 换行差异的 legacy body 会保留，因为比较是逐字节的。受管更新不创建 `.dab/backups/`；已修改文件绝不会被覆盖或备份。`dab init` 只安装缺失 skills。
- 人类输出打印 `Language: <value> (source: <source>)`。在 convergence 模式下会列出 practice 的 `create` 和 `skip` 路径，以及受管的 `update skill`、`migrate skill` 和保留类 `skip skill ... (modified|newer|legacy|unversioned|marker-mismatch)` 动作；adoption 通过 `adoption.sourceActions` 报告 practice 和受管创建。
- 现有 authored 内容永不被覆盖，但上文描述的受管未修改较旧 authoring-skill 重写和逐字节一致的 legacy marker 迁移除外；在 `dab.yaml` 中，normalize 只更新 `generated` 记录，永不更新 authored 字段。现有 `dab.yaml` 若无法解析，normalize 会以配置错误（YAML 语法错误为 `config.yaml`，schema 或版本错误为 `config.invalid`）停止并零写入；修复文件后重跑。
- Import 在每次 normalize 时运行，不只发生在 adoption 期间。物理 `.claude/agents/<name>.md` 和 `.claude/skills/<name>/SKILL.md` 条目会复制到 `.agents`，原 `.claude` 条目会备份到 `.dab/backups/<timestamp>/`，并替换为逐项符号链接。
- 保留 basename 和 skill 目录名。frontmatter `name` 不一致会警告，但不会重命名。首次 import 会复制整个 skill 目录（包括额外文件）。当 `.agents/skills/<name>` 已存在时，额外文件不会合并；它们保留在备份中并产生警告。
- 现有 `.agents` source 优先。当 `.claude` 内容不同时，normalize 保留 source、备份 `.claude`、发出警告并仍然创建链接。已指向 source 的 managed 符号链接会被跳过。
- Import 不需要 `--fix`；`--fix` 只处理非 import 的 unmanaged 冲突。`.claude/agents` 或 `.claude/skills` 上的目录符号链接是冲突，因为 DAB 逐项拥有条目。
- 已记录的 projection 符号链接发生漂移时会原地修复，不需要 `--fix`。未记录但已有 authored `.agents` source 的条目符号链接由 `--fix` 先备份再修复；没有 authored source 的链接是冲突，必须手动移除，因为 DAB 从不导入或删除 unmanaged 链接。
- 任何非法 import 候选都会阻止所有写入：不写 adoption source 文件、不 import、不备份。后续 target 预检失败时，`.claude` 保持不变，幂等的 source 副本可能已经存在。
- `--dry-run` 预览 adoption source 动作以及 import、backup、symlink 计划和计划备份路径，并运行同一预检但不写入。人类输出列出 adoption source 动作、import 动作和 adoption 备份；`--json` 提供 `adoption.imports`、`adoption.importActions` 以及计划或实际 `adoption.backups`。顶层 `actions` 在 target 动作之前包含 adoption 动作。
- Global scope 使用相同的 import 规则：`$HOME/.claude` 下的物理条目链接到 `~/.agents`，且不在 `$HOME` 根写入任何内容。
- Import 是幂等的。导入新条目的那次运行会在下一次运行时记录这些投影，因此 import 后重跑 `dab normalize` 可让 `dab detect` 干净。

JSON 输出包含顶层结果、`scope` 和 `adoption` 对象（含 `phase`、可选的 `sourcePlan`、`sourceActions`、`importActions`、`imports`、`backups` 和 `diagnostics`），以及每个启用 target 的条目。Project scope 还会追加示例之后的 `practices` 对象：

- `practices.profile` 是 manifest 的原始值（`generic` 或 `feature`）；`mode` 为 `adoption` 或 `converge`；`language` 是解析后的 `{ value, source }`。
- `created` 和 `skipped` 只描述 documentation；`skills.created`、`skills.skipped`、`skills.updated`、`skills.migrated`、`skills.modified`、`skills.newer`、`skills.legacy`、`skills.unversioned` 和 `skills.markerMismatch` 描述 authoring skills。`skills.updated` 列出被重写为当前模板的未修改受管 skills，`skills.migrated` 列出已升级的 legacy markers，其余列表列出被保留的文件。`policySkipped` 只列出因双语规则而跳过的缺失 docs；已有 docs 报告为 `skipped`。`directories` 列出要创建的 practice-owned 目录，例如 authoring skill 目录。
- dry run 中 `created`、`directories`、`skills.created`、`skills.updated` 和 `skills.migrated` 是计划值，尚未写入。在 practice 写入前被阻断的 project-scope 运行（例如非法 import、路径错误或没有启用的 target）仍返回带 diagnostics 以及计划但未写入条目的 `practices`。Convergence 在 target preflight 之前写入 practice 文件，因此被后续 target 或校验失败阻断的运行会报告已经写入的 `created` 条目；这些文件是幂等的，重跑是安全的。
- Global scope 始终省略 `practices`。由 import 产生的 `.claude/skills/dab-*` 条目出现在 `adoption.imports`，不在 `practices.skills` 中。
- 结果包含绝对 `root`；其他路径相对于该基准，包括 `gitignore.path` 和 backup 条目。
- `--dry-run` 运行同一预检和退出码，但不写入。在未初始化或 partial scope 上，它预览 adoption source，且没有 target 计划，因为 target 计划需要已写入的 source。Import 计划位于 `--json` 的 `adoption.imports`、`adoption.importActions` 和计划中的 `adoption.backups`；顶层 `actions` 和 `backups` 重复这些计划字符串和路径。
- Global scope 下 `~/.claude/settings.json` 和 `$HOME/.gitignore` 只读，normalize 会警告 global settings 尚未采用。

## `dab policy explain`

```bash
dab policy explain [--agent <name>] [--target <provider>] [--json]
```

展示 target 和 provider、运行时版本、默认模式、allow/ask/deny 规则、按执行顺序排列的 hooks、来源文件和限制。使用 `--agent` 时会追加角色的 tools、disallowed tools、effective tools、权限模式、记忆模式和后追加的 hooks。`disallowedTools` 在省略 `tools` 时仍然生效；显式空 `tools` 列表会以警告形式报告为无工具。Tool names 使用逗号分隔；对 `tools` 而言，`*` 只能单独使用。

- 没有 `--target` 时解释第一个启用的 target。
- `--target <provider>` 选择已配置的 target。启用的 target 没有 adapter 时会以 `target.unsupported` 失败。

## 退出码

| 代码 | 含义 |
|---|---|
| `0` | 成功 |
| `1` | 内部错误 |
| `2` | 用法或配置错误 |
| `3` | 校验失败 |
| `4` | Claude Code 版本不兼容 |

## JSON 输出

每个 JSON 结果都在顶层包含 `schemaVersion: 1`；嵌套 payload 继承该版本。成功的输出已排序且稳定，且与进程 locale 无关。发布可以新增字段，但删除字段或改变含义必须提升 schema version。`--json` 不能与 `--help` 或 `--version` 组合使用。错误使用相同的信封：

```json
{
  "schemaVersion": 1,
  "ok": false,
  "error": {
    "code": "usage.unknown-command",
    "message": "unknown command: wat",
    "exitCode": 2
  }
}
```

## 常见示例

```bash
dab init
dab init ~/.agents
dab detect
dab normalize --dry-run
dab normalize
dab policy explain --target claude-code
dab policy explain --agent reviewer
```

## 说明

- 生成文件永远不手工编辑。
- `.claude/settings.local.json` 归用户所有，DAB 从不读写它。
- 本阶段 global settings 和 `$HOME/.gitignore` 只读；global agents 和 skills 仍会导入，settings 的采用和合并计划单独进行。
- `--fix` 必须显式指定，因为它可能在备份后替换非 import 的冲突文件。
- `dab init` 是一次性的 full profile 初始化入口；对已有 project 或已有 global source，请使用 `dab detect` 和 `dab normalize`。
