# CLI

公开命令是 `dab`。所有命令都支持 `--json`，退出码区分配置用法、校验和后端问题。

## Scope 与 Root 发现

| 命令 | Root |
|---|---|
| `dab init [path]` | 确切的 `path` 或当前目录 |
| 其他命令 | 最近的、包含 `dab.yaml` 或 `.agents/` 的祖先目录 |

- 运行 `dab init ~/.agents` 引导 global scope。
- 从子目录运行时，其他命令向上查找到最近的项目 manifest 或 source tree。
- 位于 `$HOME/.agents` 内时，命令使用 global scope；global source root 始终是 `$HOME/.agents`。
- Project 和 global scope 独立检查和 normalize。没有 `dab global` 命令，也没有跨 scope 合并。
- v0.1 的所有命令都拒绝 Windows。

## `dab init`

```bash
dab init [path] [--profile feature] [--ai] [--dry-run]
```

Project 布局：

```text
AGENTS.md
dab.yaml
.agents/
.claude/            generated by dab normalize
```

Global 布局：

```text
~/.agents/AGENTS.md
~/.agents/dab.yaml
~/.agents/agents ... policies, hooks, memory
~/.claude/agents ... generated projections under $HOME
```

- `dab init ~/.agents` 初始化 global scope：编写源位于 `~/.agents/`，投影位于 `$HOME` 下。
- `dab init path` 把 `path` 作为确切的 source root，并在缺失时创建它。它拒绝在已有 source root 内部创建 source root。
- 扫描仓库并写入缺失的编写文件。编写源冲突会在写入前停止。未受管的 `.claude` 冲突会作为 pending 报告，交给 `dab normalize --fix`。
- 生成的 manifest 是 v2，包含 `scope`、`targets` 和 `instructions: symlink`。
- JSON 输出包含 `root`（source root）和 `scopeRoot`（路径基准）；`created`、`skipped` 以及嵌套 normalize 路径都相对于 `scopeRoot`。
- `--dry-run` 预览编写文件写入和 pending 冲突，不写入任何内容。`--ai` 让 Claude Code 生成提案，确认后才写入；不能与 `--dry-run` 同时使用。

## Manifest v2

```yaml
version: 2
scope: project
project:
  id: example
  name: Example
profile: feature
targets:
  - provider: claude-code
    enabled: true
    options:
      minVersion: 2.1.277
      instructions: symlink
paths:
  agents: .agents
  claude: .claude
generated:
  targets:
    - provider: claude-code
      settings:
        path: .claude/settings.json
        sha256: 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
      instructions:
        path: .claude/CLAUDE.md
        mode: symlink
        sha256: 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
      projections: []
```

Global manifest 位于 `~/.agents/dab.yaml`，声明 `scope: global`：

```yaml
version: 2
scope: global
project:
  id: personal
  name: Personal
profile: feature
targets:
  - provider: claude-code
    enabled: true
    options:
      instructions: symlink
paths:
  agents: .agents
  claude: .claude
```

- `scope` 必须匹配解析出的位置；不匹配是错误。
- `targets` 是必需的，且至少包含一个条目。单个条目可以设置 `enabled: false`；必须至少保留一个启用的 target，否则 normalize 和 detect 会以 `target.none` 失败。
- 启用的 target 没有 adapter 时会以 `target.unsupported` 失败。
- `generated` 由 `dab normalize` 写入；永远不要手工编辑。
- Legacy v1 manifest 会按 project scope 迁移到 v2。

## `dab detect`

```bash
dab detect [--strict] [--json]
```

只检查不写入。它验证 scope、启用的 target adapter、Claude Code 版本、祖先指令文件、指令产物、投影、settings、策略、hooks、记忆、敏感信息、AGENTS.md 大小和链接。每个 fact 输出一行 `kind name: target=status`。

- `--strict` 在存在任何 warning 时以退出码 3 结束。CI 中可用它把 unknown frontmatter 等警告变成失败。
- Global scope 会跳过祖先和个人记忆检查，因为用户级 Claude 数据不是项目产物。
- Unmanaged target path 和缺失的生成记录会作为漂移报告。

## `dab normalize`

```bash
dab normalize [--dry-run] [--fix] [--json]
```

规划或应用投影修复、`.claude/CLAUDE.md` 指令产物、`.claude/settings.json`、`dab.yaml` 生成记录和 `.gitignore`。它会在写入前预检每个启用的 target；一个 target 失败会阻止所有写入。冲突会在写入前停止。`--fix` 会在替换前把冲突文件备份到 `.dab/backups/`。

JSON 输出包含顶层结果和每个启用 target 的条目：

```json
{
  "actions": [],
  "backups": [],
  "diagnostics": [],
  "dryRun": false,
  "exitCode": 0,
  "gitignore": {
    "changed": false,
    "path": ".gitignore"
  },
  "manifestUpdated": false,
  "ok": true,
  "root": "/path/to/project",
  "schemaVersion": 1,
  "settings": {
    "changed": false,
    "path": ".claude/settings.json",
    "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
  },
  "shimAction": "none",
  "targets": [
    {
      "actions": [],
      "backups": [],
      "instructions": {
        "action": "none",
        "mode": "symlink",
        "path": ".claude/CLAUDE.md",
        "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
      },
      "provider": "claude-code",
      "settings": {
        "changed": false,
        "path": ".claude/settings.json",
        "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
      }
    }
  ]
}
```

- 结果包含绝对 `root`；其他路径相对于该基准，包括 `gitignore.path` 和 backup 条目。
- `--dry-run` 运行同一预检和退出码，但不写入。
- Global scope 下 `~/.claude/settings.json` 和 `$HOME/.gitignore` 只读，normalize 会警告 global settings 尚未采用。

## `dab policy explain`

```bash
dab policy explain [--agent <name>] [--target <provider>] [--json]
```

展示 target 和 provider、运行时版本、默认模式、allow/ask/deny 规则、按执行顺序排列的 hooks、来源文件和限制。使用 `--agent` 时会追加角色的 tools、disallowed tools、effective tools、权限模式、记忆模式和后追加的 hooks。`disallowedTools` 在省略 `tools` 时仍然生效；显式空 `tools` 列表会以警告形式报告为无工具。Tool names 使用逗号分隔；对 `tools` 而言，`*` 只能单独使用。

- 没有 `--target` 时解释第一个启用的 target。
- `--target <provider>` 选择已配置的 target。启用的 target 没有 adapter 时会以 `target.unsupported` 失败。

## 退出码

| 代码 | 含义 |
|---|---|
| `0` | 成功 |
| `1` | 内部错误 |
| `2` | 用法或配置错误 |
| `3` | 校验失败 |
| `4` | Claude Code 版本不兼容 |

## JSON 输出

每个 JSON 结果都在顶层包含 `schemaVersion: 1`；嵌套 payload 继承该版本。成功的输出已排序且稳定，且与进程 locale 无关。发布可以新增字段，但删除字段或改变含义必须提升 schema version。`--json` 不能与 `--help` 或 `--version` 组合使用。错误使用相同的信封：

```json
{
  "schemaVersion": 1,
  "ok": false,
  "error": {
    "code": "usage.unknown-command",
    "message": "unknown command: wat",
    "exitCode": 2
  }
}
```

## 常见示例

```bash
dab init
dab init ~/.agents
dab detect
dab normalize --dry-run
dab normalize
dab policy explain --target claude-code
dab policy explain --agent reviewer
```

## 说明

- 生成文件永远不手工编辑。
- `.claude/settings.local.json` 归用户所有，DAB 从不读写它。
- 本阶段 global settings 和 `$HOME/.gitignore` 只读；采用和合并计划单独进行。
- `--fix` 必须显式指定，因为它可能在备份后替换冲突文件。
