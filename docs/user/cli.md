# CLI

The public command is `dab`. All commands support `--json`, and exit codes distinguish usage, validation and backend problems.

## Scope and root discovery

| Command | Root |
|---|---|
| `dab init [path]` | the exact `path`, or the current directory |
| other commands | nearest ancestor with `dab.yaml` or `.agents/` |

- Run `dab init ~/.agents` to bootstrap global scope.
- From a subdirectory, other commands walk upward to the nearest project manifest or source tree.
- Inside `$HOME/.agents`, commands use global scope; the global source root is always `$HOME/.agents`.
- Project and global scopes are checked and normalized independently. There is no `dab global` command and no cross-scope merge.
- All commands reject Windows in v0.1.

## `dab init`

```bash
dab init [path] [--profile feature] [--ai] [--dry-run]
```

Project layout:

```text
AGENTS.md
dab.yaml
.agents/
.claude/            generated by dab normalize
```

Global layout:

```text
~/.agents/AGENTS.md
~/.agents/dab.yaml
~/.agents/agents ... policies, hooks, memory
~/.claude/agents ... generated projections under $HOME
```

- `dab init ~/.agents` initializes global scope: authored source lives in `~/.agents/` and projections live under `$HOME`.
- `dab init path` uses `path` as the exact source root and creates it when missing. It refuses to create a source root inside an existing one.
- Scans the repository and writes missing authored files. Authored conflicts stop before writes. Unmanaged `.claude` conflicts are reported as pending and left to `dab normalize --fix`.
- The generated manifest is v2 and includes `scope`, `targets` and `instructions: symlink`.
- `--dry-run` previews authored writes and pending conflicts without writing. `--ai` asks Claude Code for a proposal and writes only after confirmation; it cannot be combined with `--dry-run`.

## Manifest v2

```yaml
version: 2
scope: project
project:
  id: example
  name: Example
profile: feature
targets:
  - provider: claude-code
    enabled: true
    options:
      minVersion: 2.1.277
      instructions: symlink
paths:
  agents: .agents
  claude: .claude
generated:
  targets:
    - provider: claude-code
      settings:
        path: .claude/settings.json
        sha256: 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
      instructions:
        path: .claude/CLAUDE.md
        mode: symlink
        sha256: 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
      projections: []
```

A global manifest lives at `~/.agents/dab.yaml` and declares `scope: global`:

```yaml
version: 2
scope: global
project:
  id: personal
  name: Personal
profile: feature
targets:
  - provider: claude-code
    enabled: true
    options:
      instructions: symlink
paths:
  agents: .agents
  claude: .claude
```

- `scope` must match the resolved location; a mismatch is an error.
- `targets` is required and must contain at least one entry. Individual entries may set `enabled: false`; at least one target must stay enabled or normalize and detect fail with `target.none`.
- An enabled target without an adapter fails with `target.unsupported`.
- `generated` is written by `dab normalize`; never edit it by hand.
- A legacy v1 manifest is migrated to v2 as project scope.

## `dab detect`

```bash
dab detect [--json]
```

Runs checks without writing. It verifies scope, enabled target adapters, Claude Code version, ancestor instruction files, the instructions artifact, projections, settings, policy, hooks, memory, secrets, AGENTS.md size and links. It prints one `kind name: target=status` line per fact.

- In global scope, ancestor and personal-memory checks are skipped because user-level Claude data is not a project artifact.
- Unmanaged target paths and missing generated records are reported as drift.

## `dab normalize`

```bash
dab normalize [--dry-run] [--fix] [--json]
```

Plans or applies projection repairs, the `.claude/CLAUDE.md` instruction artifact, `.claude/settings.json`, `dab.yaml` generated records and `.gitignore`. It prechecks every enabled target before writing; one failing target blocks all writes. Conflicts stop before writes. `--fix` backs up conflicting files under `.dab/backups/` before replacing them.

JSON output includes the top-level result and one entry per enabled target:

```json
{
  "actions": [],
  "backups": [],
  "diagnostics": [],
  "dryRun": false,
  "exitCode": 0,
  "gitignore": {
    "changed": false,
    "path": ".gitignore"
  },
  "manifestUpdated": false,
  "ok": true,
  "schemaVersion": 1,
  "settings": {
    "changed": false,
    "path": ".claude/settings.json",
    "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
  },
  "shimAction": "none",
  "targets": [
    {
      "actions": [],
      "backups": [],
      "instructions": {
        "action": "none",
        "mode": "symlink",
        "path": ".claude/CLAUDE.md",
        "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
      },
      "provider": "claude-code",
      "settings": {
        "changed": false,
        "path": ".claude/settings.json",
        "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
      }
    }
  ]
}
```

- All paths are relative to the scope root, including `gitignore.path` and backup entries.
- `--dry-run` runs the same precheck and exit codes without writing.
- In global scope, `~/.claude/settings.json` and `$HOME/.gitignore` are read-only and normalize warns that global settings are not adopted.

## `dab policy explain`

```bash
dab policy explain [--agent <name>] [--target <provider>] [--json]
```

Shows target and provider, runtime version, default mode, allow/ask/deny rules, hooks in execution order, source files and limitations. With `--agent`, it adds the role's tools, disallowed tools, effective tools, permission mode, memory mode and appended hooks. `disallowedTools` applies even when `tools` is omitted; an explicitly empty `tools` list is reported as no tools with a warning. Tool names are comma-separated; for `tools`, `*` is only valid alone.

- Without `--target`, the first enabled target is explained.
- `--target <provider>` selects a configured target. An enabled target without an adapter fails with `target.unsupported`.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success |
| `1` | Internal error |
| `2` | Usage or configuration error |
| `3` | Validation failure |
| `4` | Incompatible Claude Code version |

## JSON output

Every JSON result includes `schemaVersion: 1` at the top level; nested payloads inherit it. Successful output is sorted and stable, independent of the process locale. Releases may add fields, but removing a field or changing its meaning requires a new schema version. `--json` cannot be combined with `--help` or `--version`. Errors use the same envelope:

```json
{
  "schemaVersion": 1,
  "ok": false,
  "error": {
    "code": "usage.unknown-command",
    "message": "unknown command: wat",
    "exitCode": 2
  }
}
```

## Common examples

```bash
dab init
dab init ~/.agents
dab detect
dab normalize --dry-run
dab normalize
dab policy explain --target claude-code
dab policy explain --agent reviewer
```

## Notes

- Generated files are never edited by hand.
- `.claude/settings.local.json` is user-owned and never read or written by DAB.
- Global settings and `$HOME/.gitignore` are read-only in this phase; adoption and merge are planned separately.
- `--fix` is explicit because it can replace conflicting files after backing them up.
