# CLI

The public command is `dab`. All commands support `--json`, and exit codes distinguish usage, validation and backend problems.

## Install

```bash
npx @saydone/dab --version
npx @saydone/dab init /path/to/project
```

Or install globally to use `dab`:

```bash
npm install -g @saydone/dab
dab --version
```

The npm package is `@saydone/dab`; `npx dab` resolves to a different package. Requires Node.js `>=24.9`, Claude Code `>=2.1.277`, macOS or Linux.

## Scope and root discovery

| Command | Root |
|---|---|
| `dab init [path]` | the exact `path`, or the current directory |
| other commands | nearest ancestor with `dab.yaml` or `.agents/` |

- Run `dab init ~/.agents` to bootstrap global scope.
- From a subdirectory, other commands walk upward to the nearest project manifest or source tree.
- Inside `$HOME/.agents`, commands use global scope; the global source root is always `$HOME/.agents`.
- Project and global scopes are checked and normalized independently. There is no `dab global` command and no cross-scope merge.
- Adoption resolves a phase before any manifest is required: `initialized` when the manifest parses and `.agents/` exists, `partial` when only one marker exists or the manifest is invalid, and `uninitialized` when neither exists.
- An uninitialized project anchors on the nearest ancestor with `.git`, falling back to the current directory.
- Global scope requires `~/.agents` to exist; run `dab init ~/.agents` before the first global check when it is completely missing.
- All commands reject Windows in v0.1.

## `dab init`

```bash
dab init [path] [--profile generic|feature] [--ai] [--dry-run]
```

Project layout:

```text
AGENTS.md
dab.yaml
.agents/
.claude/            generated by dab normalize
```

Global layout:

```text
~/.agents/AGENTS.md
~/.agents/dab.yaml
~/.agents/agents ... policies, notes; hooks and memory are opt-in
~/.claude/agents ... generated projections under $HOME
```

- `dab init ~/.agents` initializes global scope: authored source lives in `~/.agents/` and projections live under `$HOME`.
- `dab init path` uses `path` as the exact source root and creates it when missing. It refuses to create a source root inside an existing one.
- Scans the repository and writes missing authored files. Authored conflicts stop before writes. A regular file, dangling link or inaccessible `.agents` source parent (`agents`, `hooks`, `memory`, `notes`, `policies`, `adapters`, `rules`, `skills`) is a governed conflict that blocks every write. Unmanaged non-import `.claude` conflicts are reported as pending and left to `dab normalize --fix`.
- Init never imports existing `.claude/agents` or `.claude/skills` entries and never creates adoption backups for them. Import is `dab normalize`'s job.
- Advanced hooks and shared memory are not scaffolded by default. `.agents/hooks/` and `.agents/memory/` are opt-in; existing hooks are validated and compiled where applicable, and existing memory is preserved and validated.
- The generated manifest is v2 and includes `scope`, `profile`, `docs.language`, `targets` and `instructions: symlink`. `--profile` accepts `generic` (default) or `feature`; `feature` is a compatibility alias with the same practice behavior, and an existing authored manifest is never overwritten.
- `docs.language` controls the project documentation language: `auto` (default), `en` or `zh`. `auto` samples existing `docs/AGENTS.md`, `docs/architecture.md`, root `AGENTS.md`, `README.md`, the `package.json` description and then the locale; with no signal it uses `en`. Init reports `Language: <value> (source: <source>)` and JSON adds `language: { value, source }`.
- Init writes two single-language files, `docs/AGENTS.md` and `docs/architecture.md`, with no `.zh.md` or `.i18n.yaml` pairs. `docs/AGENTS.md` is an AGENTS file and stays pairing-exempt. Existing documentation is never overwritten.
- Init installs the `dab-doc-writing`, `dab-architecture-writing` and `dab-decision-notes` skills under `.agents/skills/`. An existing skill directory is preserved and reported as skipped. Each installed file carries a `<!-- dab-skill: <name>@<version> sha256=<hash> -->` marker. When only an importable `.claude/skills/dab-<name>` directory exists, init skips that authoring template, reports the entry as pending with `practice.skill-import-pending` and leaves the import to `dab normalize`. A non-directory entry cannot be imported: init skips the template, reports a warning pending with `practice.skill-import-conflict` and never writes or replaces the physical entry.
- The generic skeleton does not generate `.agents/rules/docs-bilingual.md`; existing authored rules are preserved. When the rule exists, missing documentation targets are policy-skipped with `practice.docs-bilingual-policy`; existing docs are preserved as skipped. Init still installs authoring skills and target output when otherwise safe.
- JSON output reports `root` (source root) and `scopeRoot` (path base); `created`, `skipped` and nested normalize paths are relative to `scopeRoot`.
- `--dry-run` previews authored writes and pending conflicts without writing. `--ai` asks Claude Code for a proposal and writes only after confirmation; proposals render through the same authored scaffold planner as the built-in profile, and `--ai` cannot be combined with `--dry-run`.

## Manifest v2

```yaml
version: 2
scope: project
project:
  id: example
  name: Example
profile: generic
docs:
  language: auto
targets:
  - provider: claude-code
    enabled: true
    options:
      minVersion: 2.1.277
      instructions: symlink
paths:
  agents: .agents
  claude: .claude
generated:
  targets:
    - provider: claude-code
      settings:
        path: .claude/settings.json
        sha256: 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
      instructions:
        path: .claude/CLAUDE.md
        mode: symlink
        sha256: 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
      projections: []
```

A global manifest lives at `~/.agents/dab.yaml` and declares `scope: global`:

```yaml
version: 2
scope: global
project:
  id: personal
  name: Personal
profile: generic
docs:
  language: auto
targets:
  - provider: claude-code
    enabled: true
    options:
      instructions: symlink
paths:
  agents: .agents
  claude: .claude
```

- `profile` is `generic` (default) or `feature`; `feature` is kept as a compatibility profile for existing workflows and grants the same practice behavior.
- `docs.language` accepts `auto` (default), `en` or `zh`; explicit `en` or `zh` skips detection. Set `language: zh` to scaffold Chinese documentation without detection:

  ```yaml
  docs:
    language: zh
  ```

- `scope` must match the resolved location; a mismatch is an error.
- `targets` is required and must contain at least one entry. Individual entries may set `enabled: false`; at least one target must stay enabled or normalize and detect fail with `target.none`.
- An enabled target without an adapter fails with `target.unsupported`.
- `generated` is written by `dab normalize`; never edit it by hand.
- A legacy v1 manifest is migrated to v2 as project scope.

## `dab detect`

```bash
dab detect [--strict] [--json]
```

Runs read-only. It resolves the scope and adoption phase before any manifest is required, so an uninitialized or partial scope returns a checklist instead of a source-root error. It then verifies scope, enabled target adapters, Claude Code version, ancestor instruction files, the instructions artifact, projections, settings, policy, optional hooks and memory when present, secrets, documentation practice, AGENTS.md size and links.

The human output prints `dab detect` first, then `Scope`, `Root` and `Profile`, groups entries as Instructions, Documentation, Agents, Skills, Rules, Policy, Hooks, Memory, Notes, Generated target and Safety, then prints `score: <ok>/<total> (<percent>%)` and one `next:` line per distinct next action. The example below is captured from a new generic project after `dab init` and `dab detect`, with the root replaced by `/path/to/project`. Paths, versions and the score depend on the project and the installed DAB version. Hooks and Memory appear only when the project has optional `.agents/hooks/` or `.agents/memory/` files, so a new project shows neither group.

```text
dab detect
Scope: project
Root: /path/to/project
Profile: generic

Instructions
  [OK] AGENTS.md
  [OK] .claude/CLAUDE.md

Documentation
  [WARN] docs/AGENTS.md (Language: en (source: docs/AGENTS.md); TODO markers at line 20, 29, 42, 48) -> use dab-doc-writing
  [WARN] docs/architecture.md (Language: en (source: docs/AGENTS.md); TODO markers at line 13, 17, 21, 25, 29, 33, 37, 41, 42, 43, 44, 45) -> use dab-architecture-writing

Agents
  [OK] implementer
  [OK] reviewer

Skills
  [OK] dab-doc-writing (version 0.1.1)
  [OK] dab-architecture-writing (version 0.1.1)
  [OK] dab-decision-notes (version 0.1.1)
  [OK] doc-sync
  [OK] feature-delivery

Rules
  [OK] generated-files
  [OK] testing

Policy
  [OK] project

Notes
  [OK] .agents/notes/

Generated target
  [OK] .claude/settings.json

score: 14/16 (88%)
next: use dab-doc-writing
next: use dab-architecture-writing
```

| Status | Meaning |
|---|---|
| `[OK]` | The fact matches. |
| `[MISSING]` | An expected fact or artifact is absent. |
| `[WARN]` | A non-fatal problem, such as drift or an environment warning. |
| `[ERROR]` | An error that needs a fix. |
| `[IMPORTABLE]` | A physical `.claude/agents` or `.claude/skills` entry that `dab normalize` can import into `.agents`. |

- `score` counts `[OK]` entries over all entries; every other status is not OK, and the score never changes the exit code.
- Hooks and Memory entries never report a missing optional file; a project without those files is not reported as missing.
- Initialized scopes run the same read-only import plan as uninitialized scopes, so an importable entry is reported as `[IMPORTABLE]` instead of as unmanaged or physical-copy projection drift.
- A regular file, dangling link or inaccessible `.agents` source parent (`agents`, `hooks`, `memory`, `notes`, `policies`, `adapters`, `rules`, `skills`) is an `[ERROR]` `path.conflict` in its group; project `rules` and `skills` practice parents keep `practice.docs-path` and `practice.skill-path`. The secret scan is best effort and may skip unreadable subtrees; source-parent access errors come from the parent probe.
- An unreadable nested skill directory is an `[ERROR]` `skill.unreadable` diagnostic for that skill. Sibling skills keep their facts and projections, and the run is never reported healthy.
- `phase` is `initialized` when `dab.yaml` parses and `.agents/` exists, `partial` when only one marker exists or the manifest is invalid, and `uninitialized` when neither exists.
- `Profile` comes from a valid manifest; an uninitialized scope, or a partial scope without a valid manifest, shows `not initialized`.
- The `Documentation` group appears in every project phase and is omitted in global scope. Preflight (uninitialized and partial scopes) checks presence, policy skips, language and path state only; content checks run on initialized scopes. Missing docs without the bilingual rule are `[MISSING]` with `dab normalize`; with the rule they are `[WARN]` policy skips with a delete-the-rule next action. On initialized scopes, broken internal links are `[ERROR]`; line-start `TODO:` or `TODO(owner):` markers and empty architecture sections are `[WARN]` with a `use dab-doc-writing` or `use dab-architecture-writing` next action. Each entry detail includes `Language: <value> (source: <source>)`. A partial scope with an invalid manifest still shows the group but suppresses the `dab normalize` next action.
- The `Skills` group reports `dab-doc-writing`, `dab-architecture-writing` and `dab-decision-notes`. A missing skill is `[MISSING]` with `dab normalize`; a path conflict is `[ERROR]`; an existing invalid `SKILL.md` is reported from source discovery instead of as preserved. Preflight (uninitialized and partial scopes) reports presence, policy skips, language and path state only. On initialized scopes, a current marker is `[OK]`; an unmodified older version is `[WARN]` with `dab normalize` and a `practice.skill-stale` warning; a legacy marker is `[WARN]` and migratable when its body matches the template; a newer or uncomparable version, a body that no longer matches its marker hash, a missing marker and a marker naming another skill are `[WARN]` and preserved; a path or read error is `[ERROR]`.
- `--strict` fails on missing practice files, TODO markers, empty architecture sections, stale skill markers and other practice warnings. `practice.docs-bilingual-policy`, `practice.skill-newer`, `practice.skill-modified`, `practice.skill-legacy`, `practice.skill-marker-mismatch` and `practice.skill-unversioned` stay informational because they describe project policy or preserved authored content.
- Uninitialized and partial scopes always exit `2` and never write; `--strict` does not change this.
- Initialized scopes keep the existing exit codes: `0` when clean, `--strict` warnings and validation failures exit `3`, and an incompatible Claude Code version exits `4`.
- `--strict` exits with code `3` on project or configuration warnings such as unknown frontmatter or drift; environment warnings such as a missing Claude Code binary do not fail.
- In global scope, ancestor and personal-memory checks are skipped because user-level Claude data is not a project artifact.
- In global scope, `~/.claude/settings.json` and `$HOME/.gitignore` are user-owned and read-only; global settings are not adopted.
- Unmanaged target paths and missing generated records are reported as drift.

`--json` keeps `targets`, `diagnostics`, `summary` and `schemaVersion: 1`, and adds `scope`, `root`, `phase`, `profile` when known, `checklist`, `score` and `nextActions`. Each checklist entry has `group`, `label`, `status`, optional `detail`, optional `file` and optional `next`. `checklist` includes the `Documentation` group and authoring skill entries in `Skills`; the resolved language is carried in `detail` as text, without a new structured field.

Uninitialized and partial scopes return this full result object with `ok: false` and `exitCode: 2`; they no longer use the `{ ok: false, error }` envelope reserved for usage, validation and backend errors. `schemaVersion` stays `1` because the fields are additive.

## `dab normalize`

```bash
dab normalize [--dry-run] [--fix] [--json]
```

Plans or applies authored source adoption, Claude imports, missing documentation and authoring skills, managed authoring-skill updates, projection repairs, the `.claude/CLAUDE.md` instruction artifact, `.claude/settings.json`, `dab.yaml` generated records and `.gitignore`. It prechecks every enabled target before writing target output; one failing target blocks all target writes. `--fix` backs up conflicting non-import paths under `.dab/backups/` before replacing them.

- Adoption runs before source-root resolution. An uninitialized or partial project gets the missing minimal authored source: `AGENTS.md`, `dab.yaml`, `.agents/policies/project.yaml` and `.agents/adapters/claude-code.yaml`, plus empty `.agents/agents`, `.agents/skills`, `.agents/rules` and `.agents/notes` directories. Hooks and shared memory are opt-in and are not adopted. Existing hooks are validated by `init`, `normalize` and `detect` and compiled where applicable; existing memory files are preserved by `init` and `normalize` and validated by `init` and `detect`. Global scope uses `.agents/AGENTS.md` and `.agents/dab.yaml` under `$HOME` and the same source subdirectories. It never creates the profile's default agents or core skills; the namespaced `dab-*` authoring skills are the exception. Use `dab init` for the full profile skeleton.
- Normalize fills missing practice artifacts in project scope. On an uninitialized or partial project, adoption includes the documentation and authoring packs; on an initialized project, convergence adds only missing docs and `dab-*` skills. Scaffolding never overwrites existing docs or skill directories, and `--fix` never replaces or backs up authored practice paths; the only managed rewrites are an unmodified older `SKILL.md` and a byte-identical legacy `SKILL.md` marker migration.
- When `.agents/rules/docs-bilingual.md` exists, missing documentation targets are policy-skipped with `practice.docs-bilingual-policy`; existing docs are preserved as skipped and the rule is preserved. Authoring skills are still installed and target writes continue.
- A blocking source or practice error (a regular file, dangling link, denied access or symlink loop at a `.agents` source parent, an escaping link or an unreadable path) blocks every write, including `.claude`. Practice writes run before target planning, so new skills are projected in the same run; a later target failure leaves the idempotent practice files in place and a rerun is safe.
- Installed `dab-*` skills are authored copies with a `<!-- dab-skill: <name>@<version> sha256=<hash> -->` marker; the hash covers the UTF-8 body after the marker line is removed. Normalize creates a missing skill, updates an unmodified copy whose marker version is strictly older than the installed DAB version, and migrates a legacy marker without a hash when the marker-stripped body is byte-identical to the current template. It preserves and warns about a modified body (`practice.skill-modified`), a newer or uncomparable version (`practice.skill-newer`), a differing legacy body (`practice.skill-legacy`), a missing marker (`practice.skill-unversioned`) and a marker naming another skill (`practice.skill-marker-mismatch`). A legacy body that differs only by CRLF line endings is preserved because the comparison is byte-exact. Managed updates do not create `.dab/backups/`; modified files are never overwritten or backed up. `dab init` installs missing skills only.
- Human output prints `Language: <value> (source: <source>)`. In convergence mode it lists practice `create` and `skip` paths and managed `update skill`, `migrate skill` and preserved `skip skill ... (modified|newer|legacy|unversioned|marker-mismatch)` actions; adoption reports practice and managed creates through `adoption.sourceActions`.
- Existing authored content is never overwritten except the managed unmodified older authoring-skill rewrite and byte-identical legacy marker migration described above; in `dab.yaml`, normalize updates only the `generated` records and never the authored fields. An existing `dab.yaml` that does not parse stops normalize with a configuration error (`config.yaml` for YAML syntax errors, `config.invalid` for schema or version errors) and zero writes; fix the file and rerun.
- Imports run on every normalize, not only during adoption. Physical `.claude/agents/<name>.md` and `.claude/skills/<name>/SKILL.md` entries are copied into `.agents`, and the original `.claude` entry is backed up under `.dab/backups/<timestamp>/` and replaced with a per-entry symlink.
- Basenames and skill directory names are preserved. A frontmatter `name` mismatch warns but does not rename. A first import copies the whole skill directory, including extra files. When `.agents/skills/<name>` already exists, extra skill files are not merged; they stay in the backup with a warning.
- Existing `.agents` source wins. When the `.claude` content differs, normalize keeps the source, backs up `.claude`, warns and still creates the link. A managed symlink that already points at the source is skipped.
- Imports do not need `--fix`; `--fix` covers non-import unmanaged conflicts. A directory symlink at `.claude/agents` or `.claude/skills` is a conflict because DAB owns entries one by one.
- A recorded projection symlink that drifts is repaired in place without `--fix`. An unrecorded entry symlink backed by an authored `.agents` source is repaired by `--fix`, which backs it up first; a link with no authored source is a conflict that must be removed manually, because DAB never imports or deletes unmanaged links.
- Any invalid import candidate blocks every write: no adoption source files, imports or backups. When a later target preflight fails, `.claude` stays untouched and an idempotent source copy may already exist.
- `--dry-run` previews adoption source actions and the import, backup and symlink plan, including planned backup paths, and runs the same precheck without writing. Human output lists adoption source actions, import actions and adoption backups; `--json` adds `adoption.imports`, `adoption.importActions` and planned or applied `adoption.backups`. Top-level `actions` includes adoption actions before target actions.
- In global scope the same import rules apply: physical entries under `$HOME/.claude` link into `~/.agents`, and nothing is written at the `$HOME` root.
- Imports are idempotent. A run that imports new entries records their projections on the next run, so rerun `dab normalize` after an import to make `dab detect` clean.

JSON output includes the top-level result, `scope` and an `adoption` object with `phase`, optional `sourcePlan`, `sourceActions`, `importActions`, `imports`, `backups` and `diagnostics`, plus one entry per enabled target. Project scope also adds the `practices` object described after the example:

- `practices.profile` is the manifest value (`generic` or `feature`); `mode` is `adoption` or `converge`; `language` is the resolved `{ value, source }`.

- In a dry run, `created`, `directories`, `skills.created`, `skills.updated` and `skills.migrated` are planned, not written. Its import plan is in `--json` under `adoption.imports`, `adoption.importActions` and planned `adoption.backups`; top-level `actions` and `backups` repeat the planned strings and paths.
- In global scope, `~/.claude/settings.json` and `$HOME/.gitignore` are read-only and normalize warns that global settings are not adopted.

## `dab policy explain`

```bash
dab policy explain [--agent <name>] [--target <provider>] [--json]
```

Shows target and provider, runtime version, default mode, allow/ask/deny rules, hooks in execution order, source files and limitations. With `--agent`, it adds the role's tools, disallowed tools, effective tools, permission mode, memory mode and appended hooks. `disallowedTools` applies even when `tools` is omitted; an explicitly empty `tools` list is reported as no tools with a warning. Tool names are comma-separated; for `tools`, `*` is only valid alone.

- Without `--target`, the first enabled target is explained.
- `--target <provider>` selects a configured target. An enabled target without an adapter fails with `target.unsupported`.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success |
| `1` | Internal error |
| `2` | Usage or configuration error |
| `3` | Validation failure |
| `4` | Incompatible Claude Code version |

## JSON output

Every JSON result includes `schemaVersion: 1` at the top level; nested payloads inherit it. Successful output is sorted and stable, independent of the process locale. Releases may add fields, but removing a field or changing its meaning requires a new schema version. `--json` cannot be combined with `--help` or `--version`. Errors use the same envelope:

```json
{
  "schemaVersion": 1,
  "ok": false,
  "error": {
    "code": "usage.unknown-command",
    "message": "unknown command: wat",
    "exitCode": 2
  }
}
```

## Common examples

```bash
dab init
dab init ~/.agents
dab detect
dab normalize --dry-run
dab normalize
dab policy explain --target claude-code
dab policy explain --agent reviewer
```

## Notes

- Generated files are never edited by hand.
- `.claude/settings.local.json` is user-owned and never read or written by DAB.
