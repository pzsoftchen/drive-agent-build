# DAB 为什么存在

更强的模型和更好的 harness 不会自动产生可靠交付。它们提高了 Agent 能做什么的上限，却没有定义应该构建什么、工作如何收敛，以及什么证据能证明结果可以接受。

DAB 是长期方向：驱动 Agent 成为构建者。当前开发专属路径是 DAD（Drive Agent Development）。本页说明 DAB 要解决哪些问题、它位于哪里，以及 DAD 任务循环和 DAB 目标循环如何关联。能力门禁和发布状态在 [路线图](../roadmap.zh.md)。

## DAB 要解决的四个问题

DAB 从四个具体失败出发。它们有顺序：前两个让 Agent 可被驾驶；第三个让单个开发任务可以完成；第四个面向更大的目标。

### 配置漂移与跨 Agent 干扰

同一个项目事实经常被复制到多个 harness 配置中。副本会漂移，生成文件被手改，target 专属设置混进共享指令。读取其他 Agent 配置的 Agent，会继承本来不属于自己的语义。

DAB 的答案是唯一的编写源（`AGENTS.md` 和 `.agents/`）、显式的逐 target 投影、所有权记录和漂移检测。Target 专属策略放在 adapter overlay 中；共享指令保持目标中立。

### 不可执行的工程纪律

项目纪律经常只存在于提示词和对话里。先写测试、文档、决策记录、最小权限和 fail loud 都只是愿望，不是配置。新的 Agent 或新的会话无法复现它们。

DAB 的答案是让纪律成为编写源和投影配置的一部分。能检查的规则变成门禁；其余规则被明确标为行为约定。模型见 [工程纪律](engineering-discipline.zh.md)。

### 未被度量的单任务交付

Agent 可以不停行动，却没有产生被接受的结果。验收常常停留在对话里，没有基线、没有固定任务集，也没有记录人工干预、成本或范围越界。

DAB 的答案是任务证据：固定任务集、确定性测试、稳定的 harness 事件和基线对比。这是 DAD 任务循环，不是 DAB 目标循环。

### 没有模型的目标级交付

更大的目标需要拆解、任务协同、集成、整体验收和跨任务学习。单任务循环不定义其中任何一项。

DAB 把目标级交付当作研究。只有当真实 DAD 使用反复产生任务循环无法解决的目标级失败时，它才启动。

## DAB 位于哪里

DAB 在概念上是位于 harness 之上的驾驶系统。本仓库实现的是它的控制面。DAB 不替代模型，不实现 Agent Loop，也不成为另一个 runtime。

- 构建者是对意图、约束、判断和验收负责的人。
- Agent 是在 harness 内执行构建工作的执行主体。
- DAB 把这些决策和项目事实转化为受治理的 harness 配置。
- Harness 使用模型和项目工具执行工作。
- 项目证据回到 DAB，驱动下一次决策。
- 只有被接受的工作才作为交付物离开循环。

这个边界很重要。如果 DAB 变成 runtime，它就会和每个 harness 竞争，也会失去共同 source 带来的跨 Agent 价值。DAB 治理配置和收敛；执行仍归 harness。

## DAD 与 DAB

DAB 是长期方向和产品名。DAD 是其中当前的开发专属路径。`dab` 命令是实现这条路径的 CLI。

| 层级 | 问题 | 范围 |
|---|---|---|
| DAD 任务循环 | 单个开发任务是否完成并被接受？ | 一个开发任务。 |
| DAB 目标循环 | 多个任务是否集成为一个被接受的目标？ | 多个任务及其集成。 |

DAD 不只是前身。它是 DAB 当前正在构建和度量的部分。当多个任务必须收敛到一个更大目标时，DAB 才开始。

## 交付层级

这些层级是嵌套的。[DAB 位于哪里](../../README.zh.md#dab-位于哪里) 展示了示意图。

Harness Loop 回答“Agent 下一步做什么”。DAD 任务循环判断单个开发任务是否完成。未来研究的 DAB 目标循环，则判断所有必要任务及集成结果是否共同构成可接受的交付。

任务完成要被记录为证据。跨任务学习是独立的改进循环，不能用完整复盘阻塞每个原子任务。

## 交付收敛

Agent 持续行动，不代表它在自治并有效收敛。收敛需要明确控制：

- 完成定义；
- 确定性检查和评审证据；
- 时间、尝试次数、成本和范围限制；
- 检查失败后的恢复策略；
- Agent 无法推进时的停止条件；
- 超出其权限时向人升级。

DAB 的作用是让这些控制成为项目配置的一部分，而不是散落在对话里。

## DAB 不是什么

- DAB 不是模型。
- DAB 不是 Agent runtime，也不替代 Harness。
- DAB 不是提示词集合。
- DAB 不是无限自治循环。
- DAB 不承诺在没有证据的情况下生成结果一定正确。

## 如何判断 DAD 与 DAB

一个概念只有改善交付才有价值。DAD 用第一次尝试即被接受的结果、人工干预和返工次数、达到验收所需的时间和成本、范围越界与门禁失败，以及已评审项目知识的复用来判断。

DAB 研究不是靠“做完 DAD”触发。只有当真实 DAD 使用反复暴露目标拆解、跨任务集成、整体验收或跨任务学习问题时，研究才启动。证据门禁在 [路线图](../roadmap.zh.md)。
